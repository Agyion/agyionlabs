Reviewed 27 September 2026. **Local changes only; no Cloudflare deployment or Search Console submission was performed.**

## Observed before the change

Read-only HTTPS requests to `https://agyionlabs.dev/` and `/app/` returned HTTP 200 and referenced `/favicon.svg`. That SVG already contains the retained gold ring (`#e8b77b`) on the dark background (`#07090d`); its SHA-256 matched both local public SVG files:

```
39f05901124d7cd5bb80ea7c82f658aff6ddd56022c0890fa298aeebc8546e35
```

The live `/favicon.ico` returned 404. Neither source page declared a PNG favicon. No legacy application `favicon.ico` or framework icon route was found outside dependencies. The fetched live `robots.txt` had content-signal comments without a Googlebot or Googlebot-Image disallow, and the fetched home/app HTML had no robots meta block. These checks do not establish how Google previously crawled or selected the icon.

Consequently, the user's report of a green search-result logo is consistent with a previously selected/cached favicon, but this review did **not** inspect Google's indexed favicon or Search Console. It is not evidence that the current live SVG remains green.

## Local change

- Preserved both existing `favicon.svg` files without modifying the design or SVG URL.
- Rasterized that exact SVG into `favicon-96.png` (96 × 96), `apple-touch-icon.png` (180 × 180), and `favicon.ico` containing 16, 32, 48 and 96 pixel PNG frames.
- Added identical copies to `landing/public` and `app/public` so standalone and combined builds agree.
- Updated `landing/index.html` and the Next metadata in `app/app/layout.tsx` to reference those files with the appropriate format/size declarations.
- Kept stable file URLs. Repeated cache-busting URL changes would not force Google to update its results.

The assembly script copies the landing public outputs through `landing/dist`; it already copies the matching app SVG separately. No assembly-script change was necessary. Fresh landing and app builds and assembly were subsequently completed by the root task. The assembled preview serves the new assets and metadata; publication is still separate.

## What Google controls

Google's current official guidance requires a crawlable homepage and favicon, a square image, and a stable URL. It recommends a size larger than 48 × 48 and lists PNG/ICO among supported formats. One favicon applies per hostname, so `/app/` does not have a separate Search favicon identity. Even an eligible icon is not guaranteed to appear. The new 96-pixel PNG and ICO provide explicit raster alternatives to the existing SVG. [Google Search Central: favicon guidance](https://developers.google.com/search/docs/appearance/favicon-in-search), checked 27 September 2026.

After publication, Google must recrawl and process the homepage and icon. Its stated timing is **several days to several weeks**, not immediate replacement. An authorized Search Console owner/full user can request homepage indexing, but repeated requests do not accelerate crawling and a request does not guarantee inclusion. No such request was submitted here. [Google Search Central: request recrawling](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), checked 27 September 2026.

Release verification should separately check the deployed HTML icon declarations, HTTP 200 and image MIME types for each icon, matching bytes, and absence of crawler blocks. Clearing a local browser cache or adding a new asset does not directly clear Google's search-result cache.
