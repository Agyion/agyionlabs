## Reproduced defects and corrections

- **Positive Fade settlement failed at real RPC simulation.** The previous root did not explicitly request claimant authorization, relying on the nested token transfer. Default RPC auth recording rejected it. Two native/WASM regressions first failed; the positive branch now requests root authorization and asserts the complete root/child auth tree. Negative and zero-price relayed settlement remain permissionless. This was first found on actual testnet after an earlier 63-test local checkpoint passed; that earlier result was incomplete.
- **Private pool self-destinations could strand consumed value.** Both contract and SDK now reject the pool itself as bridge or fee account. The missing predicate was reproduced before the fix; native and exact-WASM checks preserve roots, counters, notes and reserves, followed by a valid payout. This is a conditional fund-lock correction, not a demonstrated outsider theft.
- **A V3 number did not authenticate the selected deployment.** The public client now requires a reviewed WASM pin and checks network, requested/returned instance identity, type, ledger metadata and code hash before reporting ready and before every write. The deploy helper downloads actual deployed bytes and refuses to emit app configuration unless they exactly match the tested artifact.
- **Asset configuration could disagree.** The public factory requires the classic issuer/code/network to derive to the same token contract used by instruments.
- **Ramp could reuse stale authentication or mislabel another transfer.** Each action revalidates authentication; status responses must carry the exact requested transfer ID. Expired auth clears UI state without automatically repeating a payment.
- **Wallet availability and cache handling were misleading or fragile.** The app offers only the retained adapter that verifies its active network, Freighter. Bounded, validated nonsecret cache parsing prevents malformed provider/path metadata from breaking module import or chooser rendering. Vendor patches remain reproducible against the pinned upstream archive. This does not establish hardware-backed custody or working mobile WalletConnect.
- **Verification tools had false-pass and stale expectations.** CSP checks now reject unreviewed wildcard/remote script sources. Release checks require the selected contract/hash in byte-verified assets and matching actual browser RPC responses. A later browser run also exposed a stale readiness selector: the ready UI hides its warning banner. A stable application state marker and regression now let verification inspect real readiness without adding visible UI.

Three privacy negative tests were also repaired: invalid Pod possession and reused Envoy output randomness had masked the recipient, cap and owner checks they purported to exercise. Isolated mutants established the old false passes and new detection. Runtime/circuit artifacts did not change; the fresh default privacy suite passed 131 with four explicit optional skips. The earlier all-optional 178-test run and four real browser proofs are retained as separate evidence on unchanged runtime.

Several legacy visual QA commands recorded runtime errors but exited successfully; they now fail closed. Empty test selections are rejected, stale retired-page checks are explicitly marked historical, and browser font/animation waits have an external deadline. These fixes improve the reliability of review evidence; they do not count as contract exploit fixes.

## Remaining material limits

1. The private profile still needs independently contributed circuit setup, independently held trustee keys, authenticated deployment-bound committee setup, complete public-app integration and actual private testnet wallet/recovery/archive verification. A colluding threshold can bypass operational disclosure approval; code cannot certify independent human custody. Bridge amounts/accounts, timing, submitters and fees also remain visible.
2. Real USDC issuer behavior, extension-wallet approval and recovery, bank settlement and cross-device/mobile proving were not demonstrated by these local suites or the native-XLM smoke. The anchor/verifier directories contain documentation/configuration rather than implemented hosted services.
3. Free Fade reservations can consume availability until a missed-handoff refund. Serialized first inclusion decides the winner, not click time or network fairness; the ten-claimant tests do not fix this economic design. External attesters/venues can withhold cooperation. Key loss, issuer controls, malicious allowlisted tokens and compromised browsers/RPCs remain trust boundaries.
4. Browser storage is not global idempotency, reliable physical key erasure or production custody. Long-lived contract records require actual TTL maintenance/restoration. Reading by simulation does not renew on-chain state.
5. HTML responses now use `Cache-Control: no-transform`, with existing revalidation and immutable asset policies preserved. This prevents automatic HTML rewriting by Cloudflare. The CSP is byte-identical to the prior policy. Final live HTML matched local bytes exactly, without injected scripts or CSP violations. This also means those pages do not provide the Cloudflare JavaScript Detection signal or automatic analytics beacon. No zone, firewall or bot rules were changed. Cloudflare documents this behavior for [JavaScript Detections](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/) and [Web Analytics](https://developers.cloudflare.com/web-analytics/faq/).

The review establishes concrete improvements and tested behavior within these boundaries. It does not establish that every possible exploit is absent.
